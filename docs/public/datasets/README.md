# 数据集目录

这个目录存放**实验数据、标定文件、轨迹记录、点云样本**等结构化数据，
构建时会原样复制到网站根目录，所以文件 `pick-cup-trajectory.json` 对应的访问地址是
`/datasets/pick-cup-trajectory.json`。

## 什么时候用这个目录

适合放：

- 一次实验的完整记录（时间戳、关节角、末端位姿）
- 手眼标定结果（内参、外参矩阵）
- 位姿误差统计、成功率统计的原始表格
- 点云或图像序列的**小样本**（完整数据集请看下方）

**不建议**把原始大规模数据放进来。Git 仓库不适合存二进制大数据集，
仓库体积膨胀后无法回收，克隆会越来越慢。

## 建议的文件格式

| 数据类型 | 推荐格式 | 说明 |
| --- | --- | --- |
| 表格数据 | `.csv` | 比 `.xlsx` 小，diff 可读，任何工具能打开 |
| 配置 / 参数 | `.json`、`.yaml` | 结构化，便于引用具体字段 |
| 矩阵 / 数组 | `.npy`、`.json` | `.npy` 需 numpy 读取，`.json` 通用但更大 |
| 轨迹记录 | `.csv`、`.jsonl` | 一行一条记录，方便流式读取 |
| 日志 | `.log`、`.txt` | 先裁剪到相关片段再上传 |

**避免**：`.mat`（体积大、依赖 MATLAB）、`.pkl`（版本不兼容、有安全风险）、
压缩包 `.zip`（无法直接查看内容，别人不敢下载）。

## 引用方式

数据文件用普通链接引用，并在正文说明字段含义：

~~~markdown
本次实验的关节角与末端位姿记录：

- [抓取轨迹（CSV，1.2 MB）](/datasets/pick-cup-trajectory.csv)

字段：`t` 时间戳（秒）、`j1..j7` 关节角（弧度）、`x,y,z` 末端位置（米）。
~~~

单独写一个 `.md` 说明文件也可以，例如 `datasets/pick-cup-trajectory.md`，
和 CSV 放在一起，描述采集条件、字段定义和已知问题。

## 上传规则

| 项目 | 要求 |
| --- | --- |
| 文件名 | 用英文或拼音，不要中文、空格 |
| 单个文件 | **建议不超过 25 MB** |
| 单个数据集总量 | 建议不超过 50 MB，超过就外链 |
| 内容 | 必须脱敏，见下方提醒 |
| 配套说明 | 建议同时写清楚采集条件、字段含义、已验证/未验证 |

## 数据太大怎么办

| 情况 | 做法 |
| --- | --- |
| 几 MB 的表格、参数 | 直接放本目录 |
| 几十 MB 的点云、图像序列 | 裁剪出有代表性的样本放这里，完整数据外链 |
| 超过 100 MB | **不要放仓库**，传到实验室网盘或对象存储，文档里放链接 |

外链时请确认链接**长期有效**且访问权限设置正确，并在正文注明
「数据托管在 XXX，如需访问权限联系 XXX」。

## 安全红线

数据比文档更容易泄露信息，上传前逐项检查：

- **IP 地址、主机名**：CSV 里可能有远端 IP 列
- **设备序列号**：机器人 ID、相机序列号
- **个人路径**：`/home/你的用户名/...` 会暴露账户名
- **凭据**：配置文件里可能有 token、密码
- **内部拓扑**：网络结构、内网段

**处理方法**：用脚本批量替换（如 `sed`、Python 正则）后再上传，
不要手工改几行就以为干净了。替换后**务必用编辑器全文搜索一遍** `192.168`、
`10.`、`token`、`password` 等关键词。

::: warning 数据处理后请留一份脱敏记录
建议在数据集说明里写一句「已将 IP 列替换为 `<ROBOT_IP>` 占位符」，
这样下一位同学知道数据和现场不完全一致，避免对照时误解。
:::
